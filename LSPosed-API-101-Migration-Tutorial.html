ShortX Migration Notes

LSPosed API 101 手把手迁移教程

基于 ShortX 本次 010-upgrade-lsposed-api 迁移记录、源码实现和验证结果整理。目标是把传统 legacy Xposed 入口与 XC_MethodHook 写法迁移到 LSPosed/libxposed API 101，并完全废弃 legacy 支持。

迁移目标
仅支持 LSPosed API 101，不再声明或依赖 legacy Xposed 入口。
核心模式
XposedModule 入口 + XposedInterface.Hooker 实例拦截 + 项目内 ShortXHookParam 兼容层。
验证命令
./gradlew :patch-xposed:patch-main:compileKotlin :patch-xposed:patch-systemui:compileKotlin
./gradlew :app:assemblePrcDebug

1. 迁移前后差异

legacy XposedLSPosed API 101ShortX 迁移策略
IXposedHookLoadPackageXposedModule删除 XposedEntry.kt，使用 ShortXLSPosedHookEntry
assets/xposed_initMETA-INF/xposed/java_init.list删除旧 asset，入口写入 java_init.list
XC_MethodHookXposedInterface.Hooker用 Api101Hooker 包装 before/after lambda
MethodHookParamChain引入 ShortXHookParam，保持业务层和 MVEL 的 param 语义
XposedBridge.logXposedInterface.log引入 XposedLog 门面
AndroidAppHelper无等价公开类在 core-api 提供项目自己的 AndroidAppHelper
不要保留双入口作为“保险”。如果产品目标是 API 101-only，旧入口、旧 jar、旧 keep 规则和旧 metadata 都会制造歧义，设备上排错会非常困难。

2. 依赖和构建配置

步骤 2.1：版本目录增加 API 101 依赖

在 gradle/libs.versions.toml 中声明 Maven 依赖，不再依赖本地旧 jar。

[versions]
libxposed-api = "101.0.1"

[libraries]
libxposed-api = { module = "io.github.libxposed:api", version.ref = "libxposed-api" }

步骤 2.2：JVM hook 模块提取 AAR 内 classes.jar

io.github.libxposed:api:101.0.1 是 AAR。ShortX 的 patch-xposed 子模块是 Kotlin/JVM library，因此使用一个 Copy task 解包 classes.jar 再作为 compileOnly。

plugins {
    alias(libs.plugins.kotlin.jvm)
}

val libxposedApiAar by configurations.creating {
    isCanBeConsumed = false
    isCanBeResolved = true
}

val extractLibxposedApi by tasks.registering(Copy::class) {
    from({ zipTree(libxposedApiAar.singleFile) }) {
        include("classes.jar")
    }
    into(layout.buildDirectory.dir("generated/libxposed-api"))
    rename("classes.jar", "libxposed-api.jar")
}

dependencies {
    libxposedApiAar(libs.libxposed.api)

    compileOnly(files("${rootProject.rootDir.path}/android-sdk/31/android-31.jar"))
    compileOnly(files(layout.buildDirectory.file("generated/libxposed-api/libxposed-api.jar")))

    implementation(project(":core-api"))
    implementation(project(":core"))
    implementation(project(":external:utils"))
}

tasks.named("compileKotlin") {
    dependsOn(extractLibxposedApi)
}

同样的配置需要放到使用 API 101 类型的 patch-main、patch-common、patch-systemui。

4. API 101 入口迁移

API 101 入口继承 XposedModule。ShortX 最终把常规业务 hook 放在 onPackageReady，把 onPackageLoaded 作为极早期日志/特殊需求入口。

package tornaco.apps.shortx.services.xposed.hooks.hook

import io.github.libxposed.api.XposedModule
import io.github.libxposed.api.XposedModuleInterface
import tornaco.apps.shortx.core.BuildPropInternal
import tornaco.apps.shortx.core.annotations.DoNotStrip
import tornaco.apps.shortx.core.util.logAdapter
import tornaco.apps.shortx.services.xposed.hooks.hook.api.IPackageLoaded
import tornaco.apps.shortx.services.xposed.hooks.hook.api.ISystemServerLoaded

private lateinit var processName: String

@DoNotStrip
class ShortXLSPosedHookEntry : XposedModule() {
    override fun onModuleLoaded(param: XposedModuleInterface.ModuleLoadedParam) {
        super.onModuleLoaded(param)
        Api101Runtime.init(this, param.processName, param.isSystemServer)
        logAdapter = { _, tag, msg ->
            XposedLog.log("$tag $msg")
        }
        XposedLog.log("ShortXLSPosedHookEntry.onModuleLoaded ${param.processName} isSystemServer: ${param.isSystemServer}")
        processName = param.processName
        HookStub2.initZygote()
    }

    override fun onPackageReady(param: XposedModuleInterface.PackageReadyParam) {
        super.onPackageReady(param)
        val pkgParam = IPackageLoaded.Param(
            param.packageName,
            processName,
            param.classLoader
        )
        XposedLog.log("ShortXLSPosedHookEntry.onPackageReady: $pkgParam")
        HookStub2.packageLoaded(pkgParam)
    }

    override fun onPackageLoaded(param: XposedModuleInterface.PackageLoadedParam) {
        super.onPackageLoaded(param)
        if (BuildPropInternal.APP_IS_DEBUG) {
            XposedLog.log("ShortXLSPosedHookEntry.onPackageLoaded: $param")
        }
    }

    override fun onSystemServerStarting(param: XposedModuleInterface.SystemServerStartingParam) {
        super.onSystemServerStarting(param)
        XposedLog.log("ShortXLSPosedHookEntry.onSystemServerStarting")
        HookStub2.systemServerLoaded(ISystemServerLoaded.Param(param.classLoader))
    }
}
经验：大多数 legacy handleLoadPackage 的逻辑应迁到 onPackageReady。只有需要抢在 AppComponentFactory 或 Application 之前的极早期 hook，才放到 onPackageLoaded。

5. Hook facade 设计

迁移时不要让业务代码直接依赖 API 101 的 Chain。更稳的方式是保持原来的 beforeMethod/afterMethod 函数名，只替换底层实现。

为什么不要使用全局 callback registry

一开始可以想到这样的设计：注册时把 Member -> callback 存进内存 map，运行时用 chain.executable 回查。但是实际测试发现，注册时的 Method/Constructor 对象和运行时 chain.executable 不一定是同一个对象或可稳定 equals 命中，导致日志显示已注册，但 before/after 运行时找不到 callback。

最终采用实例 Hooker 方案：每次 hook 注册一个带 callback 的 Api101Hooker 实例，运行时直接执行实例字段里的 lambda，不再按 member 查 map。

6. 完整可复用核心代码

6.1 Api101Runtime.kt

package tornaco.apps.shortx.services.xposed.hooks.hook

import android.content.pm.ApplicationInfo
import io.github.libxposed.api.XposedInterface

object Api101Runtime {
    private var xposedInterface: XposedInterface? = null

    var isSystemServer: Boolean = false
        private set

    val xposed: XposedInterface
        get() = checkNotNull(xposedInterface) { "XposedInterface is not initialized" }

    val applicationInfo: ApplicationInfo?
        get() = runCatching { xposedInterface?.moduleApplicationInfo }.getOrNull()

    fun init(base: XposedInterface, processName: String?, systemServer: Boolean) {
        xposedInterface = base
        isSystemServer = systemServer
    }
}

注意：不要在这里维护 currentProcessName/currentPackageName/currentApplication。这类信息应通过 Android 运行时查询或通过生命周期参数传递，避免跨 package callback 污染。

package tornaco.apps.shortx.services.xposed.hooks.hook

object XposedLog {

6.3 ShortXHookParam.kt

package tornaco.apps.shortx.services.xposed.hooks.hook

import java.lang.reflect.Member
import java.lang.reflect.Method

class ShortXHookParam(
    val method: Member,
    val thisObject: Any?,
    val args: Array<Any?>,
    result: Any? = null,
    throwable: Throwable? = null,
    val isBefore: Boolean = false,
) {
    var result: Any? = result
        set(value) {
            field = value
            resultChanged = true
        }

    var throwable: Throwable? = throwable
        set(value) {
            field = value
            throwableChanged = true
        }

    var resultChanged: Boolean = false
        private set

    var throwableChanged: Boolean = false
        private set

    var skipOriginal: Boolean = false
        private set

    val methodOrNull: Method?
        get() = method as? Method

    fun returnAndSkip(value: Any?) {
        result = value
        skipOriginal = true
    }

    fun throwAndSkip(value: Throwable) {
        throwable = value
        skipOriginal = true
    }
}

迁移约定：所有希望替换返回值并阻止原方法继续执行的 before hook 使用 param.returnAndSkip(value)，不要只写 param.result = value。

6.4 Api101Hooker.kt

package tornaco.apps.shortx.services.xposed.hooks.hook

import io.github.libxposed.api.XposedInterface
import tornaco.apps.shortx.core.BuildPropInternal

class Api101Hooker(
    private val beforeCallback: ((ShortXHookParam) -> Unit)? = null,
    private val afterCallback: ((ShortXHookParam) -> Unit)? = null,
) : XposedInterface.Hooker {
    override fun intercept(chain: XposedInterface.Chain): Any? {
        if (BuildPropInternal.APP_IS_DEBUG) {
            XposedLog.log("Api101Hooker intercept - $chain")
        }
        val member = chain.executable
        val args = chain.args.toTypedArray()
        val beforeParam = ShortXHookParam(
            method = member,
            thisObject = chain.thisObject,
            args = args,
            isBefore = true,
        )
        beforeCallback?.let { hook ->
            runCatching {
                if (BuildPropInternal.APP_IS_DEBUG) {
                    XposedLog.log("Api101Hooker invoke beforeCallback - $hook $member")
                }
                hook(beforeParam)
            }.onFailure { XposedLog.log("before hook failed: $member", it) }
        }

        var result: Any? = null
        var throwable: Throwable? = null
        if (beforeParam.skipOriginal) {
            throwable = beforeParam.throwable
            result = beforeParam.result
        } else {
            try {
                result = chain.proceed(beforeParam.args)
            } catch (e: Throwable) {
                throwable = e
            }
        }

        val afterParam = ShortXHookParam(
            method = member,
            thisObject = chain.thisObject,
            args = beforeParam.args,
            result = result,
            throwable = throwable,
        )
        afterCallback?.let { hook ->
            runCatching {
                if (BuildPropInternal.APP_IS_DEBUG) {
                    XposedLog.log("Api101Hooker invoke afterCallback - $hook $member")
                }
                hook(afterParam)
            }.onFailure { XposedLog.log("after hook failed: $member", it) }
        }
        afterParam.throwable?.takeIf { afterParam.throwableChanged }?.let { throw it }
        if (!afterParam.throwableChanged) {
            throwable?.let { throw it }
        }
        return afterParam.result
    }

    companion object {
        fun before(callback: (ShortXHookParam) -> Unit): Api101Hooker {
            return Api101Hooker(beforeCallback = callback)
        }

        fun after(callback: (ShortXHookParam) -> Unit): Api101Hooker {
            return Api101Hooker(afterCallback = callback)
        }
    }
}

6.5 Hooks.kt

package tornaco.apps.shortx.services.xposed.hooks.hook

import tornaco.apps.shortx.core.logOnDebug
import tornaco.apps.shortx.core.util.Logger
import java.lang.reflect.Constructor
import java.lang.reflect.Member
import java.lang.reflect.Method

private val utilLogger = Logger("ShortXHookUtil")

fun beforeConstruct(
    clazz: Class<*>,
    beforeConstruct: (param: ShortXHookParam) -> Unit,
) {
    val constructors = clazz.declaredConstructors.onEach { it.isAccessible = true }
    require(constructors.isNotEmpty()) {
        "beforeConstruct, unable to hook this Constructor: $clazz"
    }
    constructors.forEach { constructor ->
        hookBefore(constructor, beforeConstruct)
    }
    utilLogger.d("beforeConstruct, hooked: ${constructors.toList()} for Constructor: $clazz")
}

fun afterConstruct(
    clazz: Class<*>,
    afterConstruct: (param: ShortXHookParam) -> Unit,
) {
    val constructors = clazz.declaredConstructors.onEach { it.isAccessible = true }
    require(constructors.isNotEmpty()) {
        "afterConstruct, unable to hook this Constructor: $clazz"
    }
    constructors.forEach { constructor ->
        hookAfter(constructor, afterConstruct)
    }
    utilLogger.d("afterConstruct, hooked: ${constructors.toList()} for Constructor: $clazz")
}

fun beforeMethod(
    clazz: Class<*>,
    methodName: String,
    logger: Logger = utilLogger,
    beforeMethod: (param: ShortXHookParam) -> Unit,
) {
    val methods = clazz.declaredMethods
        .filter { it.name == methodName }
        .onEach { it.isAccessible = true }
    require(methods.isNotEmpty()) {
        "beforeMethod, unable to hook this method: $clazz#$methodName"
    }
    methods.forEach { method -> hookBefore(method, beforeMethod) }
    logger.d("beforeMethod, hooked: $methods for method: $clazz#$methodName")
}

fun afterMethod(
    clazz: Class<*>,
    methodName: String,
    logger: Logger = utilLogger,
    afterMethod: (param: ShortXHookParam) -> Unit,
) {
    val methods = clazz.declaredMethods
        .filter { it.name == methodName }
        .onEach { it.isAccessible = true }
    require(methods.isNotEmpty()) {
        "afterMethod, unable to hook this method: $clazz#$methodName"
    }
    methods.forEach { method -> hookAfter(method, afterMethod) }
    logger.d("afterMethod, hooked: $methods for method: $clazz#$methodName")
}

fun afterMethod(
    method: Method,
    afterMethod: (param: ShortXHookParam) -> Unit,
) {
    method.isAccessible = true
    hookAfter(method, afterMethod)
    utilLogger.d("afterMethod, hooked: $method")
}

fun beforeMethod(
    method: Method,
    beforeMethod: (param: ShortXHookParam) -> Unit,
) {
    method.isAccessible = true
    hookBefore(method, beforeMethod)
    utilLogger.d("beforeMethod, hooked: $method")
}

private fun hookBefore(member: Member, callback: (ShortXHookParam) -> Unit) {
    hookMember(member, Api101Hooker.before(callback))
}

private fun hookAfter(member: Member, callback: (ShortXHookParam) -> Unit) {
    hookMember(member, Api101Hooker.after(callback))
}

@Suppress("UNCHECKED_CAST")
private fun hookMember(member: Member, hooker: Api101Hooker) {
    when (member) {
        is Method -> Api101Runtime.xposed.hook(member).intercept(hooker)
        is Constructor<*> -> Api101Runtime.xposed.hook(
            member as Constructor<Any>
        ).intercept(hooker)
        else -> error("Unsupported hook member: $member")
    }
}

fun ShortXHookParam.logParamsOnDebug(logger: Logger = utilLogger, printStack: Boolean = false) {
    logger.logOnDebug {
        "${method.name} - ${args.map { it }.joinToString()} ${if (printStack) Throwable().stackTraceToString() else ""}"
    }
}

fun ShortXHookParam.logParamsAndResOnDebug(
    logger: Logger = utilLogger,
    printStack: Boolean = false
) {
    logger.logOnDebug {
        "${method.name} - ${args.map { it }.joinToString()} ---> $result ${if (printStack) Throwable().stackTraceToString() else ""}"
    }
}

7. 业务 Hook 迁移示例

legacy 写法

XposedHelpers.findAndHookMethod(
    clazz,
    "onCommand",
    object : XC_MethodHook() {
        override fun beforeHookedMethod(param: MethodHookParam) {
            if (param.args[0].toString().startsWith("shortx")) {
                param.result = ShortXService.onCommand(param.thisObject as ShellCommand)
            }
        }
    }
)

API 101 facade 写法

beforeMethod(lpparam.classLoader.amsShellCommandClass(), "onCommand") { param ->
    val command = param.args[0].toString()
    if (command.startsWith("shortx")) {
        val shellCommand = param.thisObject as ShellCommand
        param.returnAndSkip(ShortXService.onCommand(shellCommand))
    }
}

关键点：要阻止原方法继续执行时使用 returnAndSkip，不要只改 result。after hook 中替换最终返回值也统一用 returnAndSkip，便于语义一致。

8. 用户动态 MethodHook 迁移

ShortX 的用户自定义 MethodHook 是核心能力。迁移目标不是让用户重建规则，而是让旧的 proto 配置继续生效。

object CustomHookUtil {
    fun installHookForRules(
        rules: List<Rule>,
        das: List<DirectAction>,
        classLoader: ClassLoader?,
        currentProcessPkgName: String?,
        lifecycle: MethodHookLifecycle,
        onMethodCall: (ShortXHookParam, MethodHook) -> Unit,
        log: (String) -> Unit
    ) {
        log("Checking rules for app: $currentProcessPkgName - $lifecycle")
        (rules.filter { it.isEnabled }.map { it.factsAndQuitFacts } + das.map { it.quitFacts })
            .flatten()
            .forEach { proto ->
                if (proto is_ MethodHook::class.java) {
                    val mh = proto unpack_ MethodHook::class.java
                    if ((currentProcessPkgName == null || mh.packageName == currentProcessPkgName)
                        && mh.lifecycle == lifecycle
                    ) {
                        log("Installing method hook: ${mh.className}-${mh.methodName}")
                        mh.install(classLoader, onMethodCall, log)
                    }
                }
            }
    }

    private fun MethodHook.install(
        classLoader: ClassLoader?,
        onMethodCall: (ShortXHookParam, MethodHook) -> Unit,
        log: (String) -> Unit
    ) {
        kotlin.runCatching {
            val clazz = Reflections.findClass(className, classLoader)
            val constraints = constraintList
            val methodsNameFiltered = ReflectionUtils.getDeclaredMethods(clazz)
                .filter { it.name == methodName }
            val methodConstraintsFiltered =
                methodsNameFiltered.filter { matchConstraints(it, constraints, log) }
            require(methodConstraintsFiltered.isNotEmpty()) {
                "No method match your constraints"
            }
            val firstMethod = methodConstraintsFiltered.first()
            if (beforeMethod) {
                beforeMethod(firstMethod) {
                    onMethodCall(it, this)
                }
            } else {
                afterMethod(firstMethod) {
                    onMethodCall(it, this)
                }
            }
        }.onFailure {
            log(it.stackTraceToString())
        }
    }
}

MVEL 表达式兼容

private fun executeMVEL(
    expression: String,
    methodHookParam: ShortXHookParam,
    log: (String) -> Unit
): String {
    val varsMap: Map<String, Any?> =
        mapOf(
            "param" to methodHookParam,
            "helper" to InjectedAndroidAppHelper()
        )
    return kotlin.runCatching {
        MVEL.executeExpression(MVEL.compileExpression(expression), varsMap)?.toString().orEmpty()
    }.getOrElse {
        log(it.stackTraceToString())
        ""
    }
}

用户原来的表达式仍然可以读取 param.args、param.result、param.thisObject、param.method，也可以读取 helper.currentPackageName 等字段。

AndroidAppHelper 替代

package tornaco.apps.shortx.core.os;

import android.app.ActivityThread;
import android.app.Application;
import android.content.pm.ApplicationInfo;
import util.Reflections;

public final class AndroidAppHelper {
    private AndroidAppHelper() {}

    public static String currentProcessName() {
        String processName = ActivityThread.currentPackageName();
        if (processName == null) return "android";
        return processName;
    }

    public static ApplicationInfo currentApplicationInfo() {
        ActivityThread am = ActivityThread.currentActivityThread();
        if (am == null) return null;
        Object boundApplication = Reflections.getObjectField(am, "mBoundApplication");
        if (boundApplication == null) return null;
        return (ApplicationInfo) Reflections.getObjectField(boundApplication, "appInfo");
    }

    public static String currentPackageName() {
        ApplicationInfo ai = currentApplicationInfo();
        return (ai != null) ? ai.packageName : "android";
    }

    public static Application currentApplication() {
        return ActivityThread.currentApplication();
    }
}

9. SystemUI 迁移要点

  • 只在 com.android.systemui 主进程执行 SystemUI hook。
  • 把 XposedBridge.log 替换为 XposedLog 或项目日志门面。
  • 保留启动顺序：SystemUI Application onCreate 后初始化 ShortX context/resources，等待 runtime ready，再安装 input monitor。
  • Quick Settings、自定义 tile、状态栏图标/label 这类 after hook 替换返回值时使用 returnAndSkip。
fun SystemUIHook.hookTile(lpparam: IPackageLoaded.Param) = kotlin.runCatching {
    if (PackageNames.systemUI == lpparam.packageName) {
        afterMethod(
            Reflections.findClass(SYSTEM_UI_CUSTOM_TILE, lpparam.classLoader),
            "handleClick"
        ) { param ->
            ShortXManagerNative.shortX?.let {
                if (it.isQSTileOptEnabled) {
                    val name = Reflections.getObjectField(param.thisObject, "mComponent") as ComponentName
                    if (name.packageName.contains(BuildPropInternal.APP_PACKAGE_NAME)) {
                        val tileName = name.className.substringAfterLast(".")
                        val tile = StatusBarTile.valueOf(tileName)
                        it.onTileClick(tile.number)
                        param.returnAndSkip(null)
                        Reflections.callMethod(sAutoHideControllerImpl, "touchAutoHide")
                    }
                }
            }
        }
    }
}.onFailure {
    logger.e(it, "hookTile")
}

10. R8/ProGuard 配置

API 101 入口、Hooker、Hook facade 不能被删。ShortX 当前使用较宽的 keep 策略，先保证迁移稳定，再考虑缩小范围。

# Xposed API 101 entry and hook callbacks.
-keep class tornaco.apps.shortx.services.xposed.hooks.hook.** { *; }
-keep class * implements io.github.libxposed.api.XposedInterface$Hooker { *; }
-keepclassmembers class * {
    public static void before(...);
    public static void after(...);
}

-dontwarn io.github.libxposed.api.XposedInterface
-dontwarn io.github.libxposed.api.XposedInterface$Hooker
-dontwarn io.github.libxposed.api.XposedModule
-dontwarn io.github.libxposed.api.XposedModuleInterface$ModuleLoadedParam
-dontwarn io.github.libxposed.api.XposedModuleInterface$PackageLoadedParam
-dontwarn io.github.libxposed.api.XposedModuleInterface$SystemServerLoadedParam
如果你使用实例 Api101Hooker，不一定需要静态 before/after keep，但保留不影响功能。若改回静态 Hooker 模式，则必须保留静态回调方法。

  2. 在支持 API 101 的 LSPosed 环境中启用模块。
  3. 确认模块 metadata 显示 API 101-only。
  4. 重启 system_server、SystemUI 或整机。
  5. 确认 ShortXLSPosedHookEntry.onModuleLoaded 有日志。
  6. 确认 onSystemServerStarting 和 onPackageReady 进入调度。
  7. 验证 system_server fact、SystemUI 手势/QS、普通 app MethodHook before/after。
  8. 验证 ShortX 自 hook 保护。
  9. 故意配置一个不存在的方法，确认只记录诊断，不影响其他 hook。

现象原因处理
注册 hook 有日志，但 before/after 不触发 callback使用全局 Member -> callback map，运行时 chain.executable 不能命中注册 key使用本文的实例 Api101Hooker，不要使用 registry 回查

最终迁移完成标准

  • de.robv.android.xposed、XC_MethodHook、XposedBridge、XposedHelpers 不再出现在活跃 hook 源码中。
  • XposedEntry.kt 删除。
  • app/src/main/assets/xposed_init 删除。
  • META-INF/xposed/module.prop 的 minApiVersion 和 targetApiVersion 都是 101。
  • java_init.list 指向 API 101 XposedModule 入口。
  • debug/release 都能打包，设备上 system_server/SystemUI/app process 三类 hook 都能验证。

附录：推荐迁移顺序

  1. 先提交当前 legacy 状态，确保可回滚。
  2. 引入 io.github.libxposed:api:101.0.1，解决 JVM 模块 AAR 解包。
  3. 创建 Api101Runtime、XposedLog、ShortXHookParam、Api101Hooker、Hooks.kt facade。
  4. 迁移入口到 XposedModule。
  5. 先迁移一个简单 system_server hook，确认 before/after 能触发。
  6. 迁移动态 MethodHook，保证用户规则不需要重建。
  7. 迁移 SystemUI hook，重点验证启动顺序和 input monitor。
  8. 清理 legacy import、旧 jar、旧 asset、旧 keep 规则。
  9. 跑编译、debug/release 打包、设备 runtime 验证。
