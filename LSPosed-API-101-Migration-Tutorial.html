ShortX LSPosed API 101 迁移教程

这是一份基于 ShortX 本次真实迁移结果整理的实操教程。目标非常明确：彻底去掉 legacy 模式，只支持 LSPosed / libxposed API 101。你照着本文改，应该可以直接落地。

最终状态：不再保留 XposedEntry、不再保留 assets/xposed_init、不再依赖 api-82.jar、不再在业务 Hook 中出现 de.robv.android.xposed.*。

1. 目标与最终边界

项最终要求
模块入口只保留 ShortXLSPosedHookEntry : XposedModule
legacy 入口删除 XposedEntry.kt
legacy asset删除 app/src/main/assets/xposed_init
legacy jar删除 patch-xposed/patch-main/libs/api-82.jar 的构建使用
hook 业务层统一使用项目内 ShortXHookParam、Hooks.kt
UI scope 请求使用 io.github.libxposed:service:101.0.0，不再依赖本地 service jar
compileSdk / targetSdk升级到 36

2. 第 1 步：升级 SDK 36

ShortX 这个项目的 SDK 版本集中定义在：

buildSrc/src/main/kotlin/tornaco/project/android/shortx/BuildConfigs.kt

修改成：

object Configs {
    const val compileSdkVersion = 36
    const val minSdkVersion = 26
    const val targetSdkVersion = 36
}
为什么一定要升到 36：io.github.libxposed:service:101.0.0 的 AAR metadata 要求依赖方至少 compileSdk 36。如果你停留在 35，就只能走“解压 AAR 里的 classes.jar”这种绕路方案。

3. 第 2 步：清理旧依赖，统一用 Maven

3.1 版本目录

在 gradle/libs.versions.toml 里声明：

[versions]
libxposed-api = "101.0.1"
libxposed-service = "101.0.0"

[libraries]
libxposed-api = { module = "io.github.libxposed:api", version.ref = "libxposed-api" }
libxposed-service = { module = "io.github.libxposed:service", version.ref = "libxposed-service" }

3.2 patch-xposed 子模块

patch-main、patch-common、patch-systemui 是 Kotlin/JVM 模块，不是 Android library，所以不能像 app/ui 那样直接消费 AAR。这里仍然要从 Maven 拉下 API AAR，再提取里面的 classes.jar 作为 compileOnly。

这是“理论上都用 Maven；个别模块需要解压 Maven 下来的包”的典型例子。

plugins {
    alias(libs.plugins.kotlin.jvm)
}

val libxposedApiAar by configurations.creating {
    isCanBeConsumed = false
    isCanBeResolved = true
}

val extractLibxposedApi by tasks.registering(Copy::class) {
    from({ zipTree(libxposedApiAar.singleFile) }) {
        include("classes.jar")
    }
    into(layout.buildDirectory.dir("generated/libxposed-api"))
    rename("classes.jar", "libxposed-api.jar")
}

dependencies {
    libxposedApiAar(libs.libxposed.api)

    compileOnly(files("${rootProject.rootDir.path}/android-sdk/31/android-31.jar"))
    compileOnly(files(layout.buildDirectory.file("generated/libxposed-api/libxposed-api.jar")))
}

tasks.named("compileKotlin") {
    dependsOn(extractLibxposedApi)
}

3.3 ui 模块

ui 是 Android library，已经升级到 compileSdk 36 之后，可以直接用 Maven service 依赖，不需要自己解压。

dependencies {
    compileOnly(libs.libxposed.api)
    implementation(libs.libxposed.service)
}

3.4 必须清理的旧依赖

  • 删除 compileOnly(files("libs/api-82.jar"))
  • 删除本地 libxposed-api.jar 使用
  • 删除本地 libxposed-service.jar / libxposed-service-interface.jar 使用
  • 不要再把 de.robv.android.xposed:api:82 放进构建路径

5. 第 4 步：入口迁移到 XposedModule

最终入口代码如下：

package tornaco.apps.shortx.services.xposed.hooks.hook

import io.github.libxposed.api.XposedModule
import io.github.libxposed.api.XposedModuleInterface
import tornaco.apps.shortx.core.BuildPropInternal
import tornaco.apps.shortx.core.annotations.DoNotStrip
import tornaco.apps.shortx.core.util.logAdapter
import tornaco.apps.shortx.services.xposed.hooks.hook.api.IPackageLoaded
import tornaco.apps.shortx.services.xposed.hooks.hook.api.ISystemServerLoaded

private lateinit var processName: String

@DoNotStrip
class ShortXLSPosedHookEntry : XposedModule() {
    override fun onModuleLoaded(param: XposedModuleInterface.ModuleLoadedParam) {
        super.onModuleLoaded(param)
        Api101Runtime.init(this, param.processName, param.isSystemServer)
        logAdapter = { _, tag, msg ->
            XposedLog.log("$tag $msg")
        }
        XposedLog.log("ShortXLSPosedHookEntry.onModuleLoaded ${param.processName} isSystemServer: ${param.isSystemServer}")
        processName = param.processName
        HookStub2.initZygote()
    }

    override fun onPackageReady(param: XposedModuleInterface.PackageReadyParam) {
        super.onPackageReady(param)
        val pkgParam = IPackageLoaded.Param(
            param.packageName,
            processName,
            param.classLoader
        )
        XposedLog.log("ShortXLSPosedHookEntry.onPackageReady: $pkgParam")
        HookStub2.packageLoaded(pkgParam)
    }

    override fun onPackageLoaded(param: XposedModuleInterface.PackageLoadedParam) {
        super.onPackageLoaded(param)
        if (BuildPropInternal.APP_IS_DEBUG) {
            XposedLog.log("ShortXLSPosedHookEntry.onPackageLoaded: $param")
        }
    }

    override fun onSystemServerStarting(param: XposedModuleInterface.SystemServerStartingParam) {
        super.onSystemServerStarting(param)
        XposedLog.log("ShortXLSPosedHookEntry.onSystemServerStarting")
        HookStub2.systemServerLoaded(ISystemServerLoaded.Param(param.classLoader))
    }
}

同时删除：

patch-xposed/patch-main/src/main/java/.../XposedEntry.kt

6. 第 5 步：建立项目内 Hook 抽象

核心原则：业务 hook 不直接碰 XposedBridge、XC_MethodHook、Chain。统一走项目内门面。

6.1 ShortXHookParam

class ShortXHookParam(
    val method: Member,
    val thisObject: Any?,
    val args: Array<Any?>,
    result: Any? = null,
    throwable: Throwable? = null,
    val isBefore: Boolean = false,
) {
    var result: Any? = result
        set(value) {
            field = value
            resultChanged = true
        }

    var throwable: Throwable? = throwable
        set(value) {
            field = value
            throwableChanged = true
        }

    var resultChanged: Boolean = false
        private set

    var throwableChanged: Boolean = false
        private set

    var skipOriginal: Boolean = false
        private set

    val methodOrNull: Method?
        get() = method as? Method

    fun returnAndSkip(value: Any?) {
        result = value
        skipOriginal = true
    }

    fun throwAndSkip(value: Throwable) {
        throwable = value
        skipOriginal = true
    }
}

6.2 Api101Hooker

class Api101Hooker(
    private val beforeCallback: ((ShortXHookParam) -> Unit)? = null,
    private val afterCallback: ((ShortXHookParam) -> Unit)? = null,
) : XposedInterface.Hooker {
    override fun intercept(chain: XposedInterface.Chain): Any? {
        val member = chain.executable
        val args = chain.args.toTypedArray()
        val beforeParam = ShortXHookParam(
            method = member,
            thisObject = chain.thisObject,
            args = args,
            isBefore = true,
        )
        beforeCallback?.invoke(beforeParam)

        var result: Any? = null
        var throwable: Throwable? = null
        if (beforeParam.skipOriginal) {
            throwable = beforeParam.throwable
            result = beforeParam.result
        } else {
            try {
                result = chain.proceed(beforeParam.args)
            } catch (e: Throwable) {
                throwable = e
            }
        }

        val afterParam = ShortXHookParam(
            method = member,
            thisObject = chain.thisObject,
            args = beforeParam.args,
            result = result,
            throwable = throwable,
        )
        afterCallback?.invoke(afterParam)
        afterParam.throwable?.takeIf { afterParam.throwableChanged }?.let { throw it }
        if (!afterParam.throwableChanged) {
            throwable?.let { throw it }
        }
        return afterParam.result
    }

    companion object {
        fun before(callback: (ShortXHookParam) -> Unit) = Api101Hooker(beforeCallback = callback)
        fun after(callback: (ShortXHookParam) -> Unit) = Api101Hooker(afterCallback = callback)
    }
}

6.3 Hooks.kt

fun beforeMethod(method: Method, beforeMethod: (param: ShortXHookParam) -> Unit) {
    method.isAccessible = true
    hookBefore(method, beforeMethod)
}

fun afterMethod(method: Method, afterMethod: (param: ShortXHookParam) -> Unit) {
    method.isAccessible = true
    hookAfter(method, afterMethod)
}

private fun hookBefore(member: Member, callback: (ShortXHookParam) -> Unit) {
    hookMember(member, Api101Hooker.before(callback))
}

private fun hookAfter(member: Member, callback: (ShortXHookParam) -> Unit) {
    hookMember(member, Api101Hooker.after(callback))
}

@Suppress("UNCHECKED_CAST")
private fun hookMember(member: Member, hooker: Api101Hooker) {
    when (member) {
        is Method -> Api101Runtime.xposed.hook(member).intercept(hooker)
        is Constructor<*> -> Api101Runtime.xposed.hook(member as Constructor<Any>).intercept(hooker)
        else -> error("Unsupported hook member: $member")
    }
}
一定不要再做 legacy / API101 双 adapter。你已经实测双支持不稳定，那就让业务层只对 API101 负责，结构会简单很多。

7. 第 6 步：迁移动态 MethodHook

目标是保留用户配置和表达式语义，但底层改成 API101。

fun MethodHook.compileExpressions(
    methodHookParam: ShortXHookParam,
    log: (String) -> Unit
): List<StringPair> {
    return expressionsList.map {
        val value = executeMVEL(it.expressionMVEL, methodHookParam, log)
        StringPair.newBuilder().setFirst(it.contextKey).setSecond(value).build()
    }
}

private fun executeMVEL(
    expression: String,
    methodHookParam: ShortXHookParam,
    log: (String) -> Unit
): String {
    val varsMap = mapOf(
        "param" to methodHookParam,
        "helper" to InjectedAndroidAppHelper()
    )
    return runCatching {
        MVEL.executeExpression(MVEL.compileExpression(expression), varsMap)?.toString().orEmpty()
    }.getOrElse {
        log(it.stackTraceToString())
        ""
    }
}

这里的关键是：MVEL 里的 param 和 helper 名字不变，用户现有表达式尽量不受影响。

8. 第 7 步：处理 XposedScope

这一步很容易踩坑。

  • io.github.libxposed:api 不包含动态 request scope 能力
  • 动态 scope 请求来自单独的 io.github.libxposed:service:101.0.0
  • 升级到 compileSdk 36 后，ui 可以直接 implementation(libs.libxposed.service)

最终代码如下：

package tornaco.apps.shortx.ui.util

import github.tornaco.android.thanos.core.pm.Pkg
import io.github.libxposed.service.XposedService
import io.github.libxposed.service.XposedServiceHelper
import tornaco.apps.shortx.core.util.Logger

object XposedScope {
    private var _service: XposedService? = null
    val service get() = _service
    private val logger = Logger("XposedScope")

    private inline fun withService(onService: (XposedService) -> Unit) {
        service?.let { onService(it) }
    }

    fun requestScope(pkg: Pkg) {
        withService {
            kotlin.runCatching {
                if (!it.scope.contains(pkg.pkgName)) {
                    logger.w("XposedScope requestScope: $pkg")
                    it.requestScope(listOf(pkg.pkgName), object : XposedService.OnScopeEventListener {})
                } else {
                    logger.w("XposedScope already scoped: $pkg")
                }
            }.onFailure {
                logger.e(it)
            }
        }
    }

    fun init() {
        logger.w("Init.")
        kotlin.runCatching {
            XposedServiceHelper.registerListener(object : XposedServiceHelper.OnServiceListener {
                override fun onServiceBind(service: XposedService) {
                    logger.w("XposedScope onServiceBind: $service")
                    _service = service
                }

                override fun onServiceDied(service: XposedService) {
                    logger.w("XposedScope onServiceDied: $service")
                    _service = null
                }
            })
        }.onFailure {
            logger.e(it)
        }
    }
}
注意新版 API：requestScope 的第一个参数是 List<String>，不是单个 String。

11. 常见坑

现象原因解决
双支持看起来能编译，运行却不稳定legacy 和 API101 生命周期、回调模型不同，业务层维护两套语义很容易出错不要双支持，直接 API101-only
ui 里 requestScope 编译不过新版签名是 List<String>改成 requestScope(listOf(pkg.pkgName), ...)
service AAR 无法直接依赖项目 compileSdk 低于 36升级 compileSdk / targetSdk 到 36
仍然被识别为支持 legacyxposed_init 没删、minApiVersion 不是 101删掉 asset，统一把 min version 改成 101
Hook 设置返回值但原方法继续执行没有调用 returnAndSkip统一改用 param.returnAndSkip(xxx)
