四角向中心滑动手势需求文档

一、需求目标

新增一种新的手势触发器：从屏幕四个角向屏幕中心滑动。

该能力用于让用户在规则中配置新的手势类事实，使 ShortX 可以识别以下类型的输入：

1. 左上角向中心滑动。
2. 右上角向中心滑动。
3. 左下角向中心滑动。
4. 右下角向中心滑动。

二、范围说明

本期需求包含以下能力：

1. 新增“四角向中心滑动”手势触发器。
2. 支持在 UI 规则编辑器中选择四个角中的一个作为触发方向。
3. 支持在运行时识别四角向中心滑动手势。
4. 支持把该手势作为规则事实参与匹配和触发动作。
5. 复用现有 UI -> services -> patch-systemui -> services -> rule engine 的整体链路。

本期明确不包含以下能力：

1. 不做用户可配置的角度偏差参数。
2. 不做用户可配置的最短滑动距离参数。
3. 不做用户可配置的角圆区半径参数。
4. 不做多段轨迹、曲线轨迹或复杂手势路径识别。
5. 不做双指、多指版本。

三、核心业务定义

该功能不是现有“边缘滑动”的参数扩展，而是一种新的手势触发器。

其核心定义如下：

1. 手势起点必须落在某一个角对应的圆形区域内。
2. 手势滑动方向必须接近“该角指向屏幕中心”的对角线方向。
3. 手势滑动距离必须达到最短阈值。
4. 单次触摸流中，识别成功后只触发一次。

四、角区域定义

四个角的定义如下：

1. 左上角：圆心位于 `(0, 0)`。
2. 右上角：圆心位于 `(screenWidth, 0)`。
3. 左下角：圆心位于 `(0, screenHeight)`。
4. 右下角：圆心位于 `(screenWidth, screenHeight)`。

每个角的起点命中区域为一个圆形区域。

只要用户手势的 `ACTION_DOWN` 起点落在该圆形区域内，就视为起点命中该角。

五、角圆区半径规则

本期圆形区域半径先定义为固定常量比例，不开放给用户配置。

建议规则：

1. 取 `min(screenWidth, screenHeight)` 作为基准长度。
2. 角圆区半径：
`cornerRadius = 0.18 * min(screenWidth, screenHeight)`

说明：

1. 使用短边比例可以避免横竖屏下圆区过大或过小。
2. 后续若体验不合适，可再调整为常量或设置项，但本期先固定。

六、滑动方向定义

“向中心滑动”定义为：

1. 左上角：理想方向为从左上指向右下。
2. 右上角：理想方向为从右上指向左下。
3. 左下角：理想方向为从左下指向右上。
4. 右下角：理想方向为从右下指向左上。

运行时通过比较“实际滑动向量”和“理想方向向量”的夹角来判断是否有效。

七、方向偏差规则

本期先采用固定常量，允许一定角度偏差。

建议常量：

1. `CORNER_SWIPE_MAX_ANGLE_DEVIATION_DEG = 30f`

说明：

1. 当实际滑动方向与理想方向的夹角小于等于 30 度时，视为方向有效。
2. 该值本期不开放给用户配置。

八、最短距离规则

本期先采用固定常量，避免点击、抖动、短距离误判。

建议常量：

1. `CORNER_SWIPE_MIN_DISTANCE_DP = 72`

说明：

1. 只有当滑动距离大于等于 72dp 时，才允许识别成功。
2. 该值本期不开放给用户配置。

九、用户功能需求

（一）规则编辑器中新增手势事实

1. 用户可以在规则事实编辑器中选择新的“四角向中心滑动”事实。
2. 用户可以在四个角中选择一个。
3. 保存后该事实作为规则触发条件参与匹配。

（二）支持编辑已有配置

1. 用户进入已有规则时，可以正确回填已保存的四角向中心滑动事实。
2. 用户可以修改原来选择的角并重新保存。

（三）支持删除和禁用

1. 该事实应与现有事实一样支持删除。
2. 该事实应与现有事实一样支持禁用。
3. 该事实应继续支持 note、tag、自定义上下文 key 等通用字段能力。

十、运行时需求

1. 系统需要在 SystemUI 输入监听链路中识别该手势。
2. 识别成功后，需要生成一个新的运行时事实并回灌到 services 层。
3. services 层需要用规则引擎对该事实进行匹配。
4. 若规则匹配成功，则按现有机制执行动作。

十一、与现有手势能力的关系

1. 本能力不替换现有 `EdgeGesture`。
2. 本能力不改变现有四边缘手势的识别逻辑。
3. 本能力应与现有边缘手势并存。
4. 本能力在架构上尽量复用现有手势链路和规则发布链路。

十二、建议的数据表达方式

本期建议新增独立的事实类型，而不是复用现有 `EdgeGesture + Gesture` 的组合表达。

原因：

1. 现有 `EdgeGesture` 的区域模型是边缘或自定义矩形。
2. 新需求的区域模型是角圆区。
3. 现有 `Gesture.SwipeFromTop/Bottom/Left/Right` 的语义无法准确表达“从某一角向中心滑动”。

十三、异常与边界处理

1. 起点不在任何角圆区：不触发。
2. 起点在角圆区，但滑动方向偏离理想方向过大：不触发。
3. 起点在角圆区，方向正确，但距离不足：不触发。
4. 单次触摸流只允许成功触发一次，避免重复触发。

十四、验收标准

1. 用户可以在规则编辑器中新增“四角向中心滑动”事实。
2. 用户可以从四个角中选择其一并保存。
3. 进入规则编辑页时可以正确回填已保存配置。
4. 从对应角向中心滑动时，规则可以正确触发。
5. 从非对应角滑动时，不会误触发。
6. 从对应角起始，但方向明显偏离中心时，不会误触发。
7. 从对应角起始，但滑动距离过短时，不会误触发。
