自定义函数功能需求文档

一、需求目标

新增“自定义函数”能力，支持用户创建、查看、编辑、删除自定义函数，并在动作编排中通过“执行函数”动作复用这些函数。该能力用于让用户把一组可复用动作封装为一个函数，通过传参执行，并返回一个字符串结果。

二、范围说明

本期需求包含以下能力：

1. 自定义函数的列表查看与详情查看。
2. 自定义函数的新建、编辑、删除。
3. 自定义函数作为动作被其他动作流引用执行。
4. 函数执行时支持传入参数。
5. 函数执行完成后支持返回字符串结果。

本期明确不包含以下能力：

1. 不做函数名称全局唯一校验。
2. 不做多种返回值类型支持，统一为 string。
3. 不做“函数级动作上下文变量”配置能力。
4. 不做函数删除拦截，仅做引用提示。

三、核心业务定义

1. 自定义函数通过函数 ID 唯一标识。
2. 函数名称仅用于展示，可重复。
3. 一个自定义函数本质上是“带参数定义的动作集合”。
4. 函数只有保存成功后，才可在“执行函数”动作中被选择。
5. 函数被引用后，运行时按函数 ID 读取最新函数配置执行，不做快照复制。

四、函数数据项

每个自定义函数包含以下配置项：

1. 函数 ID。
系统生成，用于唯一标识函数，对用户通常不可编辑。

2. 函数名称。
用户手动输入，必填，可重复。

3. 返回值类型。
固定为 string。

4. 参数定义列表。
支持添加多个，使用项目现有 Function Parameter 模型。
每个参数定义包含：
- name
- defaultValue
- isRequired
- comments

5. 动作列表。
支持添加多个动作，按顺序执行。

五、用户功能需求

（一）查看函数

1. 支持展示所有已创建自定义函数的列表。
2. 列表项至少展示函数名称。
3. 支持进入单个函数详情页查看完整配置。
4. 详情页需展示：
- 函数名称
- 返回值类型
- 参数定义列表
- 动作列表

（二）新建函数

1. 用户可新建一个自定义函数。
2. 新建时函数名称为必填。
3. 返回值类型固定为 string，无需用户自由输入。
4. 参数定义列表支持动态新增、编辑、删除。
5. 动作列表支持动态新增、编辑、删除、排序。
6. 保存成功后，该函数可被“执行函数”动作选择。

（三）编辑函数

1. 用户可编辑已存在的自定义函数。
2. 可修改函数名称。
3. 可修改参数定义列表。
4. 可修改动作列表。
5. 编辑保存后，所有按该函数 ID 引用的“执行函数”动作，后续运行时都使用最新函数内容。

（四）删除函数

1. 用户可删除已存在的自定义函数。
2. 删除前必须进行二次确认。
3. 如果该函数仍被其他动作引用，删除时需提示“该函数仍被引用”。
4. 即使仍被引用，也不阻止删除。
5. 删除后函数配置不可恢复。

六、函数作为动作使用

系统需要新增一个动作：执行函数。

其行为要求如下：

1. 用户可在动作选择器中选择“执行函数”动作。
2. 该动作支持选择一个已保存的自定义函数。
3. 该动作支持为当前调用配置参数输入。
4. 参数输入以 name/value 形式配置，参数名对应函数参数定义。
5. 用户可根据函数参数定义，为每个参数填写本次调用值。
6. 执行时通过函数 ID 读取函数最新配置并执行。

七、函数返回值规则

1. 自定义函数的返回值类型固定为 string。
2. 函数返回值来源于函数内部动作执行结果。
3. 函数内部需支持一个新动作：设置返回值。
4. 设置返回值动作用于在函数执行过程中写入最终返回值。
5. 函数最终返回最近一次设置的返回值；若未设置，则返回空字符串。

八、运行时规则

1. 执行函数时，系统读取目标函数的最新配置。
2. 执行函数时，系统将本次调用的参数输入传递给函数内部动作执行环境。
3. 函数内部动作可通过现有参数引用方式访问传入参数。
4. 如果执行函数时发现函数 ID 对应的函数不存在，则直接报错。
5. 函数不存在时，不做静默跳过。

九、校验规则

1. 函数名称必填。
2. 参数定义名称在同一个函数内应避免重复。
3. 参数定义可为空。
4. 动作列表可为空，但建议至少配置一个动作。
5. 返回值类型不需要用户额外校验，因为固定为 string。

十、交互规则

1. 查看页只需要列表和详情，不要求搜索、筛选、排序等增强能力。
2. 删除必须弹出确认提示。
3. 删除确认时，如果检测到引用关系，需要同时展示引用提示。
4. 执行函数动作在选择函数后，应自动展示该函数参数定义对应的参数输入项。

十一、与现有能力的复用要求

1. 函数参数定义继续沿用项目现有 Function Parameter 模型。
2. 函数调用参数继续沿用 name/value 形式的输入模型。
3. 参数替换继续沿用现有参数引用能力。
4. 本期不引入函数级动作上下文变量配置。

十二、异常处理要求

1. 删除被引用函数时：允许删除，但提示存在引用。
2. 执行已删除函数时：直接报错。
3. 参数缺失时：按现有参数默认值与必填规则处理。

十三、验收标准

1. 用户可以完成自定义函数的查看、新建、编辑、删除。
2. 用户可以在动作中选择“执行函数”并传入参数。
3. 执行函数时可以读取最新函数配置。
4. 函数执行时可以通过“设置返回值”动作返回字符串结果。
5. 删除已被引用函数时会出现提示和二次确认。
6. 执行已删除函数时会明确报错。
