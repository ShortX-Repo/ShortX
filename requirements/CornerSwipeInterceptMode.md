四角向中心滑动手势拦截模式需求文档

一、需求目标

为现有“四角向中心滑动”手势触发器新增一个拦截模式开关。

当用户为某个四角手势开启拦截模式后，ShortX 需要像现有边缘手势的拦截模式一样，在命中对应热区时尽早抢占输入流，从而减少 SystemUI 自身手势或其他默认行为对该手势的干扰。

二、需求范围

本期需求包含：

1. 为 `CornerSwipeToCenter` 新增拦截模式配置项。
2. 在规则触发器配置页中允许用户单独开启或关闭该开关。
3. 在 patch-systemui 侧为四角手势增加与拦截模式对应的运行时逻辑。
4. 保持与现有边缘手势拦截模式一致的整体思路：早期偷取输入流，后续再由识别器完成最终判定。
5. 保持拦截模式与手势指示器开关相互独立。

本期明确不包含：

1. 不修改现有边缘手势拦截模式的语义。
2. 不把四角热区降级成矩形热区来做拦截判定。
3. 不新增用户可配置的角热区大小。
4. 不新增用户可配置的拦截延迟或其他高级拦截参数。
5. 不把拦截模式和手势提示器绑定成同一个开关。

三、核心业务定义

四角手势的拦截模式定义如下：

1. 手势起点落在对应角圆区内。
2. 该角对应的 `CornerSwipeToCenter` 规则开启了拦截模式。
3. SystemUI 输入监视器在手势最终识别成功前，就允许 ShortX 尽早偷取该输入流。
4. 最终是否触发规则，仍然取决于现有四角手势识别逻辑，即方向和距离判定仍然必须成立。

四、与现有边缘手势拦截模式的关系

本期四角手势拦截模式应复用边缘手势现有的产品语义：

1. 拦截模式不是“触发成功后再拦截”。
2. 拦截模式是“命中热区后允许尽早偷取输入流”。
3. 拦截和最终触发是两个阶段，不应混为一谈。

同时，四角手势与边缘手势的实现差异也必须明确：

1. 边缘手势的热区模型是边缘矩形或自定义矩形。
2. 四角手势的热区模型是四个角上的圆形区域。
3. 因此四角手势不能直接复用边缘手势的矩形拦截缓存，而应使用与四角识别一致的圆形热区判定。

五、用户功能需求

（一）规则编辑器配置

1. 用户在创建或编辑 `CornerSwipeToCenter` 触发器时，可以看到“拦截模式”开关。
2. 用户可以独立配置：
   1. 角位置。
   2. 手势指示器开关。
   3. 拦截模式开关。
3. 进入已有规则时，可以正确回填该开关状态。

（二）展示与摘要

1. 当四角手势开启拦截模式时，事实摘要应能体现该配置。
2. 当四角手势未开启拦截模式时，不应误显示为已开启。
3. 老规则如果没有该字段，默认视为未开启。

六、运行时需求

1. patch-systemui 需要在规则缓存刷新时识别哪些四角手势启用了拦截模式。
2. patch-systemui 需要维护独立于边缘手势的四角拦截缓存或等价快速判定数据。
3. 输入流进入时，如果当前点命中某个已开启拦截模式的角圆区，应允许 ShortX 早期偷取该输入流。
4. 偷取输入流后，仍然由现有四角识别器继续完成最终方向和距离判定。
5. 若方向或距离不满足，规则仍然不能触发。

七、兼容性要求

1. 对于历史已保存的 `CornerSwipeToCenter` 规则，如果没有 `isIntercept` 字段，默认按 `false` 处理。
2. 对于未开启拦截模式的新规则，不应改变当前四角手势的触发行为。
3. 对于边缘手势现有逻辑，本期不应引入行为回归。

八、与手势提示器的关系

1. 手势提示器是视觉反馈能力。
2. 拦截模式是输入流所有权策略。
3. 两者必须解耦。
4. 用户可以只开启提示器，不开启拦截模式。
5. 用户也可以开启拦截模式但关闭提示器。

九、异常与边界处理

1. 起点不在任何拦截启用的角圆区内：不偷取输入流。
2. 起点在角圆区内但该规则未开启拦截模式：不因四角逻辑而偷取输入流。
3. 起点在角圆区内且已偷取输入流，但方向偏离或距离不足：不触发规则。
4. 同时存在边缘手势拦截区和四角拦截区时，系统应允许二者共同参与早期偷取判断。

十、验收标准

1. 用户可以在四角手势触发器页面配置拦截模式开关。
2. 保存后再次进入编辑页，可以正确回填该开关。
3. 老规则没有该字段时，UI 显示为未开启。
4. 开启拦截模式的四角手势在命中角圆区时可以尽早偷取输入流。
5. 四角手势最终是否触发，仍然受现有方向和距离判定约束。
6. 关闭拦截模式时，当前四角手势行为与现状保持一致。
7. 手势提示器开关与拦截模式开关可独立工作，互不影响。
