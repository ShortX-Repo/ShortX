手势提示线与动态反馈需求文档

一、需求目标

为现有和未来的系统级手势增加一层实时视觉反馈。

首期目标是为“四角向中心滑动”手势增加提示效果，让用户在手势起点命中并开始滑动后，看到一个类似系统返回手势的动态箭头/拉伸提示，从而明确当前手势方向与触发意图。

该能力后续需要可复用于普通边缘手势，而不是只服务四角手势。

二、需求范围

本期需求包含：

1. 为四角向中心滑动手势增加动态提示反馈。
2. 提示效果在用户按下并轻微滑动后出现，而不是按下即出现。
3. 提示层只做显示，不拦截触摸事件，不改变现有手势识别链路。
4. 提示视觉风格尽量接近 Android 系统返回手势的动态拉伸反馈。
5. 在架构上将该能力设计为可复用的通用手势提示层，未来可扩展到普通边缘手势。

本期不包含：

1. 不开放用户自定义提示样式、颜色、大小、动画时长。
2. 不开放用户配置“显示延迟”“显示距离阈值”等参数。
3. 不做多指手势的提示反馈。
4. 不做复杂粒子、光效、震动等增强反馈。
5. 不做普通边缘手势的首期接入实现，但方案要为后续接入预留接口。

三、核心需求定义

该能力本质上不是新的手势类型，而是现有手势检测系统上的一层运行时视觉反馈能力。

其核心行为如下：

1. 用户按下后，如果起点落在某个已启用手势的有效热区中，系统进入“候选提示态”。
2. 用户继续滑动，且位移达到一个较小的显示阈值后，提示开始显示。
3. 提示在用户滑动过程中持续更新，表现出方向感、拉伸感和一定的跟手效果。
4. 若用户继续朝有效方向滑动，提示进入更明确的“可触发”或“强化反馈”状态。
5. 若手势结束、取消、方向偏离严重或退出候选态，提示消失。
6. 若手势识别成功，提示可以做一个短暂成功态过渡后消失。

四、首期适用场景

本期首先支持以下场景：

1. 左上角向中心滑动。
2. 右上角向中心滑动。
3. 左下角向中心滑动。
4. 右下角向中心滑动。

这些场景均复用已经实现的 `CornerSwipeToCenter` 运行时识别链路。

五、后续适配目标

架构上必须支持后续扩展到普通边缘手势，包括但不限于：

1. 左边缘滑动。
2. 右边缘滑动。
3. 顶边缘滑动。
4. 底边缘滑动。
5. 未来其他基于固定起点区域和固定目标方向的手势。

六、提示显示时机

提示不能在 `ACTION_DOWN` 后立刻出现。

本期约束如下：

1. `ACTION_DOWN` 命中有效热区后，仅进入候选态，不立刻显示。
2. 当用户继续滑动，且滑动距离达到一个较小的提示显示阈值后，开始显示提示。
3. 该阈值本期先定义为内部常量，不对用户开放配置。

建议初始值：

1. `GESTURE_HINT_SHOW_DISTANCE_DP = 12`

七、提示视觉风格

提示效果应尽量靠近系统返回手势风格，重点是“方向感”和“拉伸感”，而不是一个固定不动的图标。

建议视觉特征：

1. 一个指向目标方向的箭头主体。
2. 箭头主体可随滑动距离做位移或长度变化。
3. 提示整体透明度可从低到高渐入。
4. 当接近触发条件时，提示可以增强亮度、大小或拉伸程度。
5. 取消或抬手时，提示应平滑淡出，不应突然闪烁消失。

八、提示层约束

提示层必须满足：

1. 只做展示，不拦截触摸事件。
2. 不改变现有输入事件分发、偷取、消费逻辑。
3. 生命周期与当前手势触摸流绑定。
4. 单次触摸流最多只存在一个活动提示实例。

九、状态机要求

提示层至少应包含以下状态：

1. `Idle`：无提示。
2. `Candidate`：命中有效热区但尚未达到显示阈值。
3. `Showing`：提示已经显示并随手势更新。
4. `Ready`：手势方向和距离都接近触发条件，提示进入强化反馈态。
5. `Success`：手势触发成功后的短暂完成态。
6. `Dismiss`：退出和消失过程。

十、四角手势下的方向语义

提示方向要与四角向中心滑动手势保持一致：

1. 左上角提示方向：右下。
2. 右上角提示方向：左下。
3. 左下角提示方向：右上。
4. 右下角提示方向：左上。

十一、验收标准

1. 当用户在有效四角热区按下后，不会立即显示提示。
2. 当用户轻微滑动后，提示开始显示。
3. 提示方向与当前角对应的目标方向一致。
4. 提示会随手势距离动态变化，而不是静态不动。
5. 提示层不会拦截事件，也不会破坏现有手势识别结果。
6. 手势取消、抬手或识别失败时，提示能平滑消失。
7. 手势识别成功时，提示可以给出短暂完成态反馈。
8. 本期实现应为普通边缘手势后续复用保留抽象接口。
